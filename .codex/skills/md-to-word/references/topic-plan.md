# 专题方案 Word 标准格式

本模式依据用户提供的专题方案规范；用户后续明确调整优先。保留正文措辞与顺序，仅实施指定的编号、占位与样式转换。

## 标准

| 对象 | 格式 |
|---|---|
| 全文基础 | 黑色；宋体 + Times New Roman；小五 9pt；段前/后 0；1.5 倍行距；两端对齐；无页眉 |
| 页脚 | 居中“小五号：第x页 / 共x页”；x 分别为 PAGE、NUMPAGES 字段，默认封面计入并显示页码，全篇连续 |
| 封面 | 第一页；水平居中；黑体 + Times New Roman；标题一号 26pt，第7行起；第15行起为“版本：V1.0”，四号 14pt |
| 目录 | 第二页开始，可延续多页；标题“目录”黑体三号 16pt 居中；内容宋体 + Times New Roman、小四 12pt；最多三级；一级不缩进，二/三级分别缩进2/4字符；页码右对齐、点引导线 |
| 一级标题 | 黑体三号 16pt，默认字面量“1 标题” |
| 二级标题 | 黑体 + Times New Roman 四号 14pt，字面量“1.1 标题” |
| 三级标题 | 黑体 + Times New Roman 小四 12pt，字面量“1.1.1 标题” |
| 非表格正文 | 宋体 + Times New Roman 小四 12pt，首行缩进2字符，1.5倍行距 |
| 单行小标题 | 普通段落，不进入目录；黑体 + Times New Roman 小四；字面量“一、”“二、”…，不使用 Word 编号 |
| 段落式分点 | 字面量“（1）”“（2）”…，不使用 Word 编号 |
| 短句式分点 | 字面量“1. ”“2. ”…，不使用 Word 编号 |
| 表格 | 宋体 + Times New Roman 小四；段前/后0，1.3倍行距；左右居中、垂直居中；单元格上边距0.15cm；仅黑色实线横线，顶/底线1.5pt，中间横线0.5pt；无竖线；首行加粗、底色 D9D9D9 |
| 表题 | 表格上方独立段落“表章号.章内序号 表名”，例如“表5.5 文件上传参数说明”；黑体 + Times New Roman 五号10.5pt、加粗、居中，无缩进，段前/后0、1.5倍行距；与表格首行同页，不进入目录 |
| 图片占位 | 单独一段“此处需替换为XXX图片”，无缩进、居中；下一行“图x 图片名称”，黑体 + Times New Roman 五号10.5pt、加粗、居中 |

西文字体按实际字体名称 **Times New Roman** 设置。正文/目录/表格的12pt覆盖全文基础9pt。“第7/15行”经用户确认采用小四、1.5倍行距的18pt基准行：标题顶部位于正文区108pt处，单行标题后版本顶部位于252pt处。标题字号26pt，行框39pt，中间留105pt；不能用15行26pt空段堆叠。标题换行会改变版本位置，必须预览后按实际标题高度减少中间留白，不缩小指定字号。

纸张和页边距用户未另行指定，沿用转换器A4和现有页边距；“正页居中”按封面文字水平居中解释，垂直位置按指定行号。

## 内容结构

- 有下级标题时，父标题与首个下级标题直接相接；发现夹在中间的正文/表格时脚本报错，明确内容归属后调整工作副本。不擅自删除或挪到任意小节。
- 唯一开头H1作为封面标题，下面H2/H3/H4映射一级/二级/三级正文标题。多个H1为正文一级标题，此时用 `--title` 指定封面标题。
- 标题不得跳级；四级及以下结构标题需先明确是否改为单行小标题。已有数字编号与结构一致则保留，不一致报错；已有中文章节编号须先确认转换和正文引用，不自动双重编号。
- 单行小标题用普通段落“一、内容”，不要写成 Markdown 标题。混合分点样式在源中显式写普通段落，例如 `（1）内容` 或转义 `1\. 内容`，保留字面编号。
- Markdown 有序/无序列表默认统一转“（1）”形式；全篇短句列表可传 `--list-style short`。不能仅凭句子长短推断业务层次。列表展开保留原内容和顺序。
- Markdown 图片 `![系统架构](路径)` 转为占位和图注，不读取路径或下载图片。本模式有意不嵌入真实图片；若用户要求实图，另行按其指令处理并记录差异。图片需独占段落、替代文字非空；表内图片或混合行内图片报错。
- 现有纯内部链接列表目录可替换为TOC；有其他正文混杂时需先明确范围，不能静默清除。

## 表题与编号

- 每张表必须有表题。编号按正文一级标题的章号和本章表格出现顺序生成，进入新章从1重新计数；“表5.5”是第5章第5张表，与小节5.5无关。使用字面编号，不宣称为 Word 自动题注字段；增删表格后重新转换，并核对正文引用。
- 优先保留原生表格题注或紧邻表格上方的独立段落。工作副本推荐写 `表：文件上传参数说明`，也支持 `表5.5 文件上传参数说明`。已有编号与实际顺序不符时报错，不静默改动引用。两种题注同时存在时报错，避免重复。
- 缺少表名时，执行转换前根据表格内容在工作副本补充简短准确的名称，不改源文件，不虚构业务含义。脚本兜底使用最近章节标题加“说明”，交付前必须检查其是否准确、是否需要区分同节多表，不能把兜底名称当作语义验收通过。
- 表题使用与图注相同的 `caption` 样式配置，保持在表格上方并与首行同页。跨页表格重复表头，不新增表号；正文中的“见表5.5”是普通引用文字，调整编号后需人工核对。

## 使用

```bash
python3 "<skill目录>/scripts/convert.py" "方案.md" \
  --profile topic-plan --version V1.0 \
  --output "方案.docx" --report "/临时目录/专题方案检查.json"
```

本标准为默认且唯一标准，`--profile topic-plan` 可省略。封面自动生成，无需 `--cover`。需要时补 `--title "专题方案名称"`。输入和输出保护、表格与链接检查沿用原转换器。

## 验收

1. 查看检查JSON。内容检查针对明确转换后的AST；标题编号、列表标记和图片占位是预期改变，不将其描述为原文逐字等价。
2. 在Word中更新全部字段及整个目录，保存后渲染。TOC/PAGE/NUMPAGES是实际字段，脚本不伪造页码；`updateFields`仅是更新请求，不能保证所有阅读器自动更新。
3. 用可用渲染器逐页检查：封面标题及版本位置、第二页目录、三级缩进和点线、正文换页、表题名称与按章编号、表题与首行同页、跨页重复表头和横线、图注同页、中文字体及页脚总页数。目录增长后正文页码必须再次核对。
4. 不通过移除内容或降低指定字号来解决溢出。长标题、宽表格或长单元格需要在保持标准的前提下调整布局并重新渲染。
5. 没有渲染/字段更新环境时，报告“结构检查通过，目录字段及视觉分页待验证”，不声称达到最终排版验收。

完整可执行样式参数见 [topic-plan.json](../profiles/topic-plan.json)，不依赖其他报告标准。自定义样式使用 [配置覆盖](profile-configuration.md)；JSON不改变专题模式的编号、图片占位和结构检查规则。
