# 导航与信息精简

来自 AIProbe 页面批注迭代：侧栏开关迁移、统一窗口工具栏、删除重复品牌区、合并项目入口、精简项目下拉。适用于工作台与桌面工具；营销页、首次使用引导和需要强品牌识别的场景需另行判断。

## 先确定区域职责

逐项判断：它提供什么独有信息、承担什么操作、使用频率如何、是否已在别处出现。若移除后既不损失上下文也不增加操作成本，优先移除；若有功能价值但位置重复，合并入口。

| 常见现象 | 优先调整 | 保留的能力 |
| --- | --- | --- |
| 侧栏品牌、宣传副标题、项目卡片占据多行 | 压缩品牌露出，或将项目切换放到已有顶部上下文区域 | 项目识别、切换、新建入口 |
| 顶部路径和侧栏切换器重复显示同一项目 | 让顶部项目名本身成为轻量下拉入口 | 父子项目关系、当前页面名称 |
| 折叠按钮单独占一个导航行 | 放入稳定的窗口工具区，与业务导航分开 | 折叠后仍可展开、键盘操作、可访问名称 |
| 切换菜单包含重复分组标题、配置入口和多条新建动作 | 直接列项目，按需缩进；低频创建操作集中到次级菜单 | 大项目配置入口、独立与子项目创建 |
| 提示文字占多行但动作不明显 | 用简短动作标题和一行原因说明组织 | 真实计数、阻断原因和下一步 |

不要将“精简”理解为删除功能。页面主标题仍可能用于确认当前位置；表单中的项目名仍可能是编辑对象，它们不一定与顶部上下文重复。操作型菜单先满足高频切换，再考虑低频管理；不要为几个项目新增搜索框、标签和统计卡片。

## 窗口工具区与侧栏

- 用户希望获得桌面工具的整体秩序时，优先考虑贯穿窗口的顶部工具栏，下方再并列侧栏与业务内容。侧栏展开和收起不应使开关本身追随分隔线移动。
- 折叠开关采用带名称与提示的图标按钮；设置页、无项目状态也需有恢复导航的入口。已有停靠浏览器强制收窄的行为要保留并验证。
- 对齐图标的视觉中心与文字起点，而不只是给外层相同 padding。图标容器宽度、图标到文字的距离、选中背景的外延应分别定义；选中状态不能改变内容位置。
- 分组标题靠近所属项目，弱化对比；不要通过大段留白拉开已经清楚的分组。折叠后可用细分隔线替代分组文字。
- 本项目当前参考值：工具栏 52px，侧栏 224px / 折叠 64px，图标 16px，图标中心距左侧 32px，文字起点 52px。新组件先复用实际变量与组件配置，不到处硬编码这些数值。

### Electron 与浏览器的边界

- 先查看 BrowserWindow 配置和平台识别方式，再调整原生标题栏。只在目标平台启用对应样式；macOS 可使用真实系统窗口按钮，Windows/Linux 保留其平台约定。
- 浏览器预览不绘制假的红黄绿按钮。由可信预加载桥暴露最小只读平台信息区分宿主，避免以普通浏览器所在操作系统冒充 Electron。
- 自定义标题栏要给原生按钮预留位置：空白区域可拖动，按钮、链接、菜单触发器及输入区域必须可操作。检查全屏、缩放以及 WebContentsView 停靠后的边界与遮挡。
- 说明主进程配置通常需重新创建窗口后生效。未进行桌面端实测时明确标记原生按钮和拖动行为未验证，不用网页截图替代结论。

## 项目切换菜单

- 直接显示可识别的项目名；父项目作为可点击项保留，子项目通过适度缩进表示归属。不要把父项目名称与“概览与共享配置”拆成两个占行区域。
- 当前项目同时用选中底色与勾选表达。长名称截断后仍有完整查看方式，多个同名项目必须能通过父级上下文区分。
- 项目间的分隔线表达真实关系，不在每行之间加边框；对于少量项目不必加“独立项目”等低价值标题。
- 将低频创建入口集中到“新建…”菜单。若按当前父项目提供子项目入口，表单需正确预选父级，并允许选择其他合法父级；不得因为压缩菜单使已有创建能力不可达。
- 次级菜单应支持点击和键盘，不依赖悬停。检查 Escape 关闭、焦点恢复、窄屏边缘定位和长列表滚动；顶层滚动样式不能裁剪子菜单。
- 本项目 240px 菜单宽度、约 34px 行高可作紧凑桌面的起点；按真实名称长度、字体缩放与触控需求调整。不为达到固定高度而缩小文字。

## 迭代与验收

1. 将用户批注转为可检查的问题，例如“重复上下文占据三行”或“切换菜单混入三种创建入口”。判断是否也存在于共用组件或相邻区域，在授权范围内一次处理。
2. 先移除或合并重复结构，再调间距、图标和颜色。设计参考图用于提取对齐与层级关系，不照抄其品牌、数据或窗口按钮。
3. 用实际操作验证：切换父/子项目后，顶部名称、侧栏菜单和主体一致；新建入口打开正确表单；取消后不创建数据；折叠后入口仍可达。
4. 在相同视口、主题和数据状态下比较前后。等数据加载和弹层动画结束再保存截图，截图应包括足够上下文供用户判断，必要时再补局部图。
5. 恢复测试时临时改变的视口和主题；保留用户希望看到的最终页面。补充项目设计文档中的最终决策与实际限制，不把过时的验证结果当作本轮结果。

这些经验来自本项目的实际迭代，不要求所有侧栏去掉品牌、所有操作合并为菜单，或所有窗口改为自定义标题栏。每次以当前任务和使用频率判断。
