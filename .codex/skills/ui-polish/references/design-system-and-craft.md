# 设计系统与逐层打磨

用于整体视觉改版、去模板感或涉及多个组件的主题调整。局部修复只读取相关部分。

## 1. 从观察到方向

先记录真实问题，使用“位置 → 现象 → 对任务的影响 → 调整方式”，避免只有“高级感不足”这类主观判断。重点检查不一致的间距、竞争的强调色、装饰性图标、空泛文案、重复卡片和难辨认的状态。

用五项简短信息约束设计，沿用可信的现有品牌，不将这些内容变成必须等待批准的表单：

| 项目 | 要回答的问题 |
| --- | --- |
| 产品 | 用户是谁，此页面帮助他完成什么任务？ |
| 性格 | 用两三个具体词描述，例如精确、沉稳、直接；避免只写现代、高级、简洁。 |
| 视觉语境 | 产品属于什么工作环境？测试工具可借鉴仪表、执行记录与代码编辑器的秩序。 |
| 内容重点 | 哪一两个真实内容区域值得最高视觉关注？例如失败用例详情或执行进度。 |
| 识别细节 | 哪一个小细节能持续服务产品？例如与真实状态绑定的执行阶段标记。 |

检查“换掉产品名后，是否仍可用于任何产品”。若是，优先改善业务文案、真实内容组织和识别细节，不再增加背景效果。识别细节必须对应现有功能，不能伪装成不可用的按钮或快捷键。

## 2. 建立可实现的设计系统

实施前明确布局方式、色彩角色、字体层级、间距、圆角、阴影和状态。记录实际选择与理由，避免堆砌多个互相冲突的风格名称。

- **色彩**：通常采用一个中性灰阶、主/次/辅助三类文本和一个主要强调色；成功、警告、失败等语义色独立保留。导航与外框保持克制，丰富色彩留给有意义的内容。
- **密度**：按浏览、编辑、监控等任务决定。测试工具可较紧凑，但不能以过小文字或命中区域换取密度。
- **差异程度**：成熟品牌优先微调；无统一规范的界面才建立新的方向。局部页面例外不应破坏全局组件的一致性。
- **动效**：工具界面默认低强度。持续执行状态可以保留必要反馈，其余动画应与操作有因果关系。
- **变量迁移**：先列出旧值对应的语义角色，再按组件替换并查看效果；区分背景表面、文本、边框、焦点环和选中态，避免一个品牌色承担所有职责。

跨页面工作或用户要求沉淀规范时，优先更新已有设计文档。没有时可使用 `design-system/aiprobe/MASTER.md` 保存最终全局决策，`pages/<page>.md` 只记录页面差异。页面文件仅覆盖明确列出的项，其余继承全局规范。单页小修不必生成这些文件，未验证的建议不要写成既定标准。

### 可选使用 UI UX Pro Max 检索

仅当已安装且找到真实 `scripts/search.py` 路径时使用其引擎；本技能不自带脚本或数据，不运行虚构路径。没有安装时依据本文件继续完成设计，不将缺少可选引擎视为阻塞。

- 整体方向用 `--design-system`，单个问题用明确的 `--domain`，实现问题用检测到的 `--stack`。运行前查看该版本的帮助，确认参数支持。
- 查询保持一个意图和 2–5 个有效关键词。例如 `developer testing dashboard`、`keyboard focus modal`、`error summary validation`；不要把所有验收项拼成一次查询。
- 核对返回内容是否符合产品、平台和框架版本；不相关时收窄查询重试一次，仍不匹配则使用明确标注的一般设计判断。
- 风格目录是候选建议，不是品牌决策。原生移动端的 pt/dp、触觉反馈、安全区规则不能直接当作桌面 Web 的像素规范。

## 3. 逐层打磨

参考 Unslop 的顺序，在同一层覆盖全页后再进入下一层。若结构问题使页面不可用，先修复结构。以下数值是缺少现有规范时的起点，应按中文排版、内容密度、平台和真实渲染调整。

| 层次 | 执行要点 | 检查重点 |
| --- | --- | --- |
| 间距 | 优先 4px 基础节奏，局部光学校正可用 2px；同类行、按钮与面板尺寸一致，组内小于组间 | 图标、标签、数值各自对齐；避免零散 margin 修补 |
| 色彩 | 建立中性色阶与语义角色，消除无意义的渐变文字、彩色光晕和霓虹描边 | 主操作清楚；深色层次依靠表面明度；弱文本仍可读 |
| 图标 | 复用同一套图标与笔画规范，常用 16/18/20px，统一图标容器和文本间距 | 去掉没有信息价值的装饰；保留有意义的状态与品牌资产 |
| 文案 | 先确定文案长度再精修排版，标题指出当前上下文，按钮使用动作词 | 比较数据注明基准；删除空泛宣传，不虚构功能、数据或效果 |
| 字体 | 有限的字号和字重；中文优先可读性，数字可用 tabular-nums | 统一时间、百分比、耗时和数值精度；不对小字使用负字距 |
| 布局 | 保留已有功能、内容与用户阅读顺序，调整区域比例、对齐和内容宽度 | 桌面工作区充分利用窗口；不套营销页居中窄栏或大 Hero |
| 细节 | 统一圆角、边框和控件状态；内嵌圆角结合外层圆角与间距校正 | 表头、悬停、选中、焦点和运行状态可区分，统计信息无需全部装入胶囊 |
| 视觉内容 | 优先用真实结果、代码、日志和有信息价值的图表形成重点 | 没有相关内容就不补装饰图；不靠填充卡片制造“丰富” |
| 动效 | 优先 opacity/transform，约 120–220ms 可作为短反馈起点，按情境调整 | 不制造布局跳动；无无意义循环或弹跳；减少动态效果偏好生效 |

### 数据与交互细节

- 趋势使用折线，比较使用条形，进度使用进度条；只有实际存在的数据关系才引入图表。一个序列不使用无意义的彩虹配色，多个序列需可辨识的图例和非颜色线索。
- 图表、日志、测试详情应服从当前任务，不强行让每页都有一个大图表。统计数字不为了装饰附加随机微型趋势线。
- 装饰图标从可访问性树中隐藏；独立操作图标提供名称与适用的 expanded、pressed、selected 状态。优先使用原生语义按钮、链接和表单控件。
- 弹窗检查初始焦点、焦点约束和关闭后的返回位置；浮层与固定栏不能遮挡键盘焦点。
- 表单保留标签、字段级错误与已输入内容；多错误场景适用时提供可聚焦、能定位字段的错误汇总。
- 区分图标视觉尺寸与点击区域。触控 Web 通常争取约 44 CSS px 的舒适目标；紧凑桌面控件按实际交互、间距与可访问性要求验证，不照搬原生端 pt/dp 单位。

## 4. 验收

以最初的问题清单逐项复查，同一窗口和数据状态下比较修改前后。重点验证页面导航、主要操作、列表或详情、长文本和浮层；主题、窄窗口、缩放与键盘操作按本次影响范围覆盖。

- 在侧边预览或分屏环境中，先检查导航占用比例。内容过窄时可按断点收为图标栏，但需保留可访问名称、提示和手动展开入口，并验证窗口跨越断点后的状态。
- 切换页面后先等待实际数据或明确空状态出现，再评价布局；骨架屏、异步加载中间态和侧栏动画帧不能作为最终验收截图。表格允许自身横向滚动，但页面容器不应被表格撑宽。

完成意味着问题已被修复且功能可用，不只是装饰减少。保留已验证和未验证项目的区别；不为了满足固定截图次数提前停止修复，也不反复扩大检查范围。
