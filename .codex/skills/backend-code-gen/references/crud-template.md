# 场景选择与生成范围

## 标准 CRUD

先确定业务归属，再生成必要 Entity、BO/VO、Mapper、Service、Controller 和迁移。新增功能通常落入现有模块；新 Maven 模块额外读取 [POM](pom-template.md)。参考 operation/HelpDoc 的结构，不复制其字段、租户例外或未实现校验。

按 [业务契约](contract.md) 确定创建/完整编辑/部分更新语义。校验约束、转换、DDL 和返回字段一起核对。完整 CRUD 也不默认包含导入导出、统计或菜单管理。

## 只读查询与统计

复用现有实体和 Mapper，只增加查询 BO、VO 及实际需要的方法。分页使用 PageQuery/TableDataInfo；聚合 SQL 检查租户、逻辑删除、排序和结果计数。不因为新增查询就创建新表或写接口。

## 静态字典与下拉

先查系统字典和 domain/enums；具体选择见 [枚举与字典](constants-template.md)。纯代码枚举不建 Entity/Mapper。下拉只返回约定 code/label，不把枚举序号当业务代码。

## 主子表

明确未传/null 是否保留、空集合是否清空；检查数量、重复项、父子归属。主子写入同一事务。关系可丢弃时才考虑删后插；有历史、审计或外部引用则按差异更新并保留 ID。

主表分页后收集 ID，批量读取关联并分组组装 VO；空集合跳过查询。不把 forEach insert 称为批处理；使用当前 Mapper/批量能力，不能改变主 Service 泛型以保存子实体。

## 文件引用

先确认项目实际使用的 OSS/文件服务及公开接口，不假定存在 File 实体。绑定前验证文件存在、有效性、所属者/租户与访问权限。解绑不等于删除物理文件，是否删除取决于共享引用和生命周期。VO 返回遵循现有下载授权机制，不暴露内部路径或存储凭据。

## 状态变化

为审核、发布、启停等操作定义独立 BO/方法；写明原状态、目标状态、操作者与副作用。使用归属 + 原状态的条件更新，零行更新按项目约定返回冲突。事务、并发和外部副作用检查见 [正确性](correctness.md)。
