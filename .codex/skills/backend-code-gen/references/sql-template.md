# Flyway 与数据模型

迁移集中在 `runjian-admin/src/main/resources/flyway/sql/mysql/` 和 `postgresql/`，由 `FlywayConfig` 按数据源或配置选取；模块内随意创建 db/migration 文件不一定会执行。

- 新建/变更表使用新增版本迁移，不向 `script/sql` 追加增量；该目录主要是初始化基线参考。
- 同一个功能模块的数据库交付使用一份统一的版本迁移 SQL：在同一文件中按顺序放置建表、修改表结构、索引/约束，以及该功能需要的菜单、字典、配置等初始化数据。不要为每张表、每个字段修改或每批初始化数据分别生成 SQL 文件。
- MySQL 与 PostgreSQL 是同一功能的两份方言脚本，不是额外拆分的功能脚本；两份脚本保持同一交付范围和执行顺序。
- 命名沿用 `V{YYYYMMDD}.{NN}__{作者}_{模块}_{简述}.sql`。作者取已知项目标识，不编造；不明确时按已有无作者描述形式并说明。
- 选号前扫描目标方言目录，版本数字+点，防止同日冲突；不能改已应用脚本的内容、名称或版本。
- 如果功能后续再次变更，不能为了保持“一份文件”而修改已经执行的迁移；以该功能模块的新版本迁移承接变更，并在交付说明中关联原功能迁移。
- MySQL/PostgreSQL 按本次支持范围生成对应语法；不将 MySQL DDL 直接复制成 PostgreSQL。
- 不自动执行 migrate/repair。启动应用会触发迁移，不能作为普通静态验证。

## 表设计核对

新表遵循项目 `t_<模块标识>_<业务表名>` 风格，已有表不重命名。常见 ID 为 BIGINT 雪花；不再使用 UUID VARCHAR。按实际基类生成 `create_dept/create_by/create_time/update_by/update_time`，MySQL 业务及审计时间沿用 DATETIME。

租户表包含 tenant_id；平台共享表根据实际模型设计，不能为绕过隔离随意加入 tenant.excludes。del_flag 常用 CHAR(1)，默认值、删除值与实体/插件配置核对，不能机械复制某个旧表。

逐字段确认长度、精度、可空性、默认值和索引。唯一索引明确租户/所属者维度及逻辑删除后能否重建；应用查重不能替代约束。新增 NOT NULL 列先考虑存量数据回填，收窄字段先检查兼容性。

菜单/按钮权限确需变更时放入对应迁移，对齐 Controller 权限码和现有菜单层级，避免 ID 冲突。无结构或配置数据变化就不生成 SQL。

项目 Flyway 占位符前缀为 `#(`、后缀为 `)`，实际以配置为准。迁移完成情况需查日志/历史记录；应用启动成功不证明迁移执行成功。
