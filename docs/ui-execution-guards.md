# UI 执行约束与可变数据断言

## 本轮实现

- 桌面探索通过 `open_project(project_id, env, case_id)` 读取已持久化执行计划，不重新调用模型转换。旧计划缺少原子检查时需要重新转换。
- `assertion_coverage(check_ids)` 绑定下一条真实断言，一次一个原子检查。断言执行后清除映射。缺项阻止 `case_step` 和脚本保存；依赖项必须先通过。
- `precondition_status` 显示当前证据；允许报告“不满足/无法验证”，不允许手动声明通过。失败后不能重开项目来清空本次门禁。新一轮探索使用新会话。
- 每次工具调用后保存 `.aitest/ui-executions/<run-id>.json`，保留检查、阻断原因与录制步骤。删除断言录制后撤销其覆盖；历史文件不是下次执行的通过凭证。
- 操作后的快照等待数据请求结束、可见加载状态消失及短暂稳定期。超时返回未就绪；文档/XHR/fetch 的 502/503/504 返回环境阻塞，记录方法、主机和路径，不记录查询参数。
- 同一目标失败后允许一次不同工具方法恢复；恢复仍失败阻断本次执行。自由文本视觉定位按当前阶段限制，成功 DOM 操作后解除该阶段的未解决定位失败。
- Element Plus 下拉值读取和回放绑定原控件，读取其选中项，不按预期文字重新选择目标。

## 数据变化

`expect_collection` 在稳定容器中读取当前可见字段集合，支持 `min_count`、`max_count`、`contains`、`equals`。默认非空；明确验证空结果时需指定 `min_count=0,max_count=0`。

例如，“至少有多个对象”使用数量下界；“搜索结果名称包含关键词”使用每项包含规则，不将当前总数和其它记录名称写入脚本。跨步骤值比较继续使用 `read_value` 与 `expect_observed(name)`；用例明确指定的输入和期望仍保留。

探索、调试和生成脚本共用集合判断实现。定位范围及字段 CSS 来自页面观察，不能先按预期筛掉错误记录。工具只验证当前已加载集合，不证明未加载分页或虚拟列表的所有记录。

## 边界

门禁证明每个计划检查有成功录制的断言、依赖顺序及正文前覆盖，不能仅靠 ID 判断断言是否在语义上完整证明原文。映射仍需对照审阅。

当前结果等待只用于探索操作后的快照，不声称已经为全部旧脚本增加网络等待。长轮询可能导致未就绪，不能用旧列表忽略它。旧脚本不自动改写，缺少原子覆盖的脚本不能作为本轮新计划的完整缓存复用。

没有业务名称、租户、渠道或模型专用判断。当前未增加全分页遍历、动态业务对象替换及自动造数。
