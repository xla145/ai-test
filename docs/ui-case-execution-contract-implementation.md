# UI 结构化定位与字段断言优化记录

日期：2026-11-14（Asia/Taipei）
状态：代码已实现并验证；真实业务环境及实际 Qwen3-VL 模型切换后仍需验收。

## 1. 本次实现

### 1.1 结构化目标进入生产工具

`browser.ai_locate` 新增可选 `target`，支持页面上下文、区域/对话框/列表行/表单项/选项列表、控件类型及精确身份。服务端编译定位描述，自动推断 fill/check/click；旧 prompt 调用仍兼容。

调用模型前检查范围是否存在且唯一；模型返回后再检查落点所属范围、控件类型、关联标签、名称和目标文字。描述本身对应多个控件时拒绝，不因某个控件有唯一 CSS 或 data-testid 就擅自选中。列表行通过精确业务 key 绑定，前缀相同的其他记录不算匹配。

`page` 用于模型上下文，不能代替实际页面 URL/业务状态的前置检查。`scope` 和控件身份由工具验证；范围类型目前使用标准语义结构和 Element Plus 表单结构，无法识别时明确失败。

### 1.2 选择器必须指向采集时的同一个元素

页面内使用 WeakMap 为采集的元素分配临时身份。候选选择器不只检查匹配数为 1，还需确认解析到原元素。删除原节点后出现另一个同名按钮时，旧 ref 不再自动操作它。

临时身份不写入回归脚本；脚本使用可重现的区域、字段和业务标识。显式范围在控件归一化、取值、录制、调试和生成代码时保留，兼容旧步骤中只有一层范围的格式。

### 1.3 修复下拉选中值断言串位

自动采集命名区域和表单项范围。`expect_value` 生成的定位器不得依赖预期值，也不能通过位置编号掩盖字段身份缺失。

反例：故障切换字段为“错误渠道”，普通路由字段为“阿里云源”。新生成的字段断言在逐步执行和独立 Playwright 回放中都正确失败；正常值时通过。

这是对新录制脚本的修复，旧 spec/steps 文件不会自动重写。此前可能串位的用例需要重新探索并独立回放。

### 1.4 修正前置条件处理

- UI 角色必须与项目配置精确匹配，不再按名称相近替换。
- `data_refs` 为空时仍核对文字前置条件，不能直接跳过数据依赖检查。
- 用例规范检查保留显式 data_refs，包括不符合数字编号正则的模型名。
- 生成和探索提示按“页面 → 区域 → 对象 → 控件 → 单个动作 → 明确结果”组织，检查步骤与预期的触发关系，拆开下拉展开与选项选择。

文字用例的语义审查仍由 Agent 按规则执行；完整执行用例独立入库、批量转换和业务覆盖的服务端准入工作流尚未接入。本次完成的是生成提示、结构化定位、操作、录制和回放主路径。

## 2. Qwen3-VL 配置

在全局设置中：

1. 模型名填写服务商实际提供的 Qwen3-VL 系列名称，例如 `qwen3-vl-plus`、`qwen3-vl-flash` 或部署的实际名称。
2. “Midscene 视觉模型族”选择 `qwen3-vl`。
3. 在用途分配中选择该视觉模型，保存后重新开始探索任务。

标准 Qwen3-VL 名称已有自动识别，本次补充了精确名称、plus、flash 和命名空间名称的测试；设置页增加选择说明。没有修改用户保存的模型名称、服务地址或凭据。

| 原生 target 的真实模型流程 | 6/6 步骤正确，3/3 完整回放通过 |

MCP 全套初次运行遇到 Python 依赖路径问题，以及并行运行时一个 5 秒测试超时。使用已有 `.release/engine-deps` 的临时 Python 包装入口，并以单 worker 完整复测通过；未修改系统 Python 或安装新依赖。

真实模型流程直接把 `target` 传给生产 `ai_locate`，不是实验编译器先生成 prompt 后绕开新接口。流程为：输入模型标识、编辑指定行、设置开关、打开备用渠道、选择选项、保存。回放使用新浏览器上下文，不调用模型。

本轮实际使用当前配置的 `qwen3.8-omni-flash`，仅实验进程指定 `qwen3-vl` 适配。结果验证了新代码路径，不代表尚未切换的实际 Qwen3-VL 模型已验收。测试页面为本地可重置夹具，不涉及真实 dev 业务写入。
