# UI 测试与 Midscene 优化方案

日期：2026-11-15
状态：核心链路已实施，模型评测与生产验收仍需按固定样本运行
适用范围：通用 UI 测试平台能力；不包含渠道、模型、Key 等业务判断。

## 1. 结论

本次独立实验验证了两件事：

- Midscene 可以完成跨菜单、跨滚动区域的实际 UI 验证。以“模型详情展示完整配置”为例，使用 `qwen3.8-omni-flash` 完成了列表、详情、编辑页之间的路由、价格、请求路径和兜底配置核对。
- 现有脚本和报告中已确认的多项不稳定发生在“自然语言用例 → 探索步骤 → 确定性脚本 → 回放断言”的转换层。典型问题包括菜单顺序错误、不可见区域被当作不存在、跨区域内容放在同一条视觉断言中、把显示格式差异当成值差异、登录态在新页面上下文中丢失以及动态测试数据被硬编码。

本次过程同时观察到视觉模型对字段别名理解失败，以及忽略“允许小数显示位数不同”的指令。模型能力、脚本设计和平台集成均有影响，目前不能量化各自占比。

一次成功不能代表稳定性。后续必须使用固定数据和固定环境重复运行，分别统计模型、集成、脚本回放和环境失败。

## 2. 已观察到的问题

### 2.1 探索与回放混淆

探索时页面可能已经展开菜单、打开抽屉或保留筛选条件；生成脚本直接继承了这些状态，导致独立回放时出现“先点击子菜单、再展开父菜单”等错误。

### 2.2 视觉断言范围过大

详情页的基本信息、路由、定价、请求匹配、兜底配置不一定同时出现在视口内。一次断言要求模型同时确认所有区域，会把“当前不可见”误判成“页面不存在”。

### 2.3 断言类型不匹配

- 数值字段使用字符串比较，`1.0000` 与 `1.00000000` 被误判为不同值。
- 选中值可能从组件内部搜索 input 读取，而不是从选中展示区域读取。
- `visualCheck` 只能保存截图并进入人工复核，不能当作自动通过。

### 2.4 用例和数据不稳定

组合筛选实际返回“暂无数据”，但原始前置数据尚未完整核实，不能直接认定是数据缺失。应先核对条件是否正确、请求是否完成、已知候选是否满足筛选条件：确认数据不存在才阻断；已确认存在符合条件的数据而列表为空则记录待排查的断言失败。不得删除非空断言或更换筛选条件制造通过。分页需要的样本数量应提前核实。

### 2.5 模型与模型族差异

同一服务上的 `qwen3.8-omni-flash` 能识别页面中的“兜底渠道”；`qwen3-vl-plus` 曾将“备用渠道”和“兜底渠道”视为不同字段。模型切换需要基准测试，不能按模型名称直接推断效果。

### 2.6 会话边界不明确

已登录原页面可以继续执行，但新建页面上下文不应默认视为继承了登录态。执行器必须显式声明会话、角色、环境和页面，不应依赖浏览器当前活动页。

## 3. 目标架构

采用四层职责：

```text
用例契约与前置条件
        ↓
Midscene 观察、定位、操作
        ↓
确定性读取与断言适配层
        ↓
可回放 Playwright 脚本与分类报告
```

Midscene 负责：

- 理解页面和自然语言意图；
- 找到目标区域和控件；
- 在需要时滚动、展开和执行操作；
- 提供页面观察结果。

确定性层负责：

- 读取输入值、选中值、开关状态、列表行和 URL；
- 做数值、文本、状态、集合和前后值比较；
- 处理 Element Plus 等组件的真实控件；
- 生成可独立回放的定位器和脚本。

模型不得决定：

- 选择哪个业务对象来替代原始对象；
- 用近似角色替代指定角色；
- 删除或弱化预期条件；
- 把前置条件缺失当成通过。

## 4. P0 改造项

### 4.1 运行会话显式化

为每次 UI 任务建立 `UiRunContext`：

```ts
interface UiRunContext {
  projectId: string;
  env: string;
  role: string;
  baseUrl: string;
  sessionId: string;
  pageId?: string;
  viewport: { width: number; height: number; deviceScaleFactor: number };
}
```

要求：

- 探索、试跑、调试、回放都使用同一个上下文定义；
- 页面切换只通过角色和页面标识选择，不依赖当前活动页；
- 新标签页即便在同一 BrowserContext 中也必须重新核验登录态；Cookie/localStorage 共享不保证 sessionStorage 和内存状态共享；
- 首期优先复用已登录原页面；无头运行需要明确的登录流程或已验证的会话恢复策略，不擅自复制 token；
- 登录失效时返回 `AUTH_REQUIRED`，引导用户登录，不进入业务操作；
- 报告记录实际角色、页面 URL、会话 ID 和是否复用了现有登录态。

涉及模块：`desktop/src/main/index.ts`、`desktop/src/main/orchestrator.ts`、`mcp-servers/src/ui/runner.ts`、`mcp-servers/templates/ui/aitest-embedded.ts`。

### 4.2 生成后干净复跑

脚本生成完成后必须执行一次独立复跑：

1. 回到用例入口页面；
2. 恢复角色会话；
3. 按声明的入口流程重置菜单、弹窗、筛选和临时选择状态，保留登录；不全量清除存储，也不自动清理业务数据；
4. 只执行生成脚本；
5. 对照原始步骤和预期结果；
6. 通过后才允许进入“待确认”。

探索现场通过只代表“探索完成”，不能代表脚本可回放。

### 4.3 分区观察与分区断言

将长流程拆成“动作 → 等待 → 观察区域 → 确定性读取 → 断言”：

```text
打开详情
  → 观察基本信息
  → 读取模型名、状态
滚动到路由
  → 读取普通渠道和上游模型
滚动到定价
  → 读取输入价、输出价、倍率
滚动到请求匹配
  → 读取路径
滚动到兜底
  → 读取备用渠道和备用上游模型
```

`aiAssert` 只用于需要视觉判断的内容；普通字段优先由适配层读取。

### 4.4 结构化目标与动作意图

扩展 `ai_locate`：

```json
{
  "page": "模型管理",
  "scope": [
    { "kind": "dialog", "name": "模型详情" },
    { "kind": "form_item", "name": "备用渠道" }
  ],
  "control": "select",
  "label": "备用渠道",
  "intent": "open_select"
}
```

首期动作：`click`、`fill`、`open_select`、`select_option`、`set_checked`、`read_value`。

以下为建议新增/统一的能力，需对齐已有 target/intent schema 后兼容扩展，不能当成当前已支持的 API。

返回结果必须分别标记：

- `text_verified`：文字匹配；
- `scope_verified`：作用域匹配；
- `control_verified`：控件类型匹配；
- `actionable`：当前可操作；
- `unique`：作用域内唯一。

文字匹配通过不能单独代表控件定位成功。

区域可见性恢复需有边界：每步最多 3 次有方向的滚动，记录滚动容器和前后视口；区域或页面状态不再变化时停止并返回证据不足。等待优先使用页面稳定信号或目标条件，不用固定睡眠掩盖加载问题。副作用动作遇到网络不确定时先检查执行结果，不直接重放。

### 4.5 通用组件适配层

新增独立模块，例如 `mcp-servers/src/ui/components.ts`，不要继续把组件细节堆进 `browser.ts`。

首期适配：

- Element Plus `select`：wrapper、listbox、选中展示值分离；
- `switch/checkbox`：按状态设置，禁止盲目点击；
- 抽屉/弹窗：识别滚动容器和 footer 遮挡；
- 表格行：按业务 key 或稳定文本限定行；
- 表单项：label、输入控件和错误信息绑定；
- teleport 弹层：绑定当前打开的 listbox，排除隐藏副本。

## 5. P1 改造项

### 5.1 统一断言类型

新增通用断言：

```ts
type UiAssertion =
  | { kind: "text"; target: Target; expected: string; mode?: "exact" | "contains" }
  | { kind: "number"; target: Target; expected: number; tolerance?: number }
  | { kind: "boolean"; target: Target; expected: boolean }
  | { kind: "url"; expected: string }
  | { kind: "set"; target: Target; expected: string[] }
  | { kind: "same_value"; left: Target; right: Target; normalize?: "number" | "trim" };
```

数值断言使用严格的十进制解析与显式单位规则，比较 1.0000 与 1.00000000 时应相等；禁止通用地删除所有非数字字符（可能破坏负数、百分比、范围和单位倍率）。空字符串、null、NaN 与无法解析的文本均为读取失败，不转换成 0。金额优先使用十进制库，容差由契约显式指定；只有已声明换算关系时才能比较不同单位。

DOM/组件值是常规字段的优先来源。视觉提取返回类型、区域、截图和时间戳，未知值必须为空并阻止比较，不得凭上下文补全。需要视觉判定的用例结果保留人工复核门禁。

### 5.2 前置条件检查与阻断

执行前把用例前置条件拆成：

- 角色条件；
- 页面条件；
- 数据存在性；
- 数量/分页条件；
- 可执行性条件。

检查失败返回：

```text
blocked.precondition
blocked.data
blocked.auth
blocked.environment
```

阻断不计入通过或失败，不自动更换对象、角色或筛选条件。

### 5.3 失败分类和有限恢复

统一分类：

- `model_unavailable`；
- `model_output_invalid`；
- `target_missing`；
- `target_ambiguous`；
- `control_mismatch`；
- `obscured`；
- `auth_required`；
- `precondition_missing`；
- `assertion_failed`；
- `environment_error`。

同一目标、动作和页面状态最多一次有依据的恢复。恢复必须改变条件，例如重新滚动、限定弹窗、等待弹层或重建 ref；重复发送同一点击不算恢复。

### 5.4 脚本与契约绑定

在 `steps.json` 中保存：

- 用例内容 hash；
- 环境；
- 角色；
- 关键前置条件快照；
- 生成时模型和版本；
- 结构化目标和断言类型。

保存验证指纹：脚本及依赖辅助文件版本、用例/契约版本、环境配置版本、有效角色绑定、数据准备规范版本、运行模式及关键视口策略。只将影响执行语义的配置纳入指纹，不包含密钥或每次变化的 token；动态数据的实际状态每次运行核验，而非每次变化都重新生成脚本。

当前 UiWorkflow 主要绑定环境名和 spec 内容 hash，无法覆盖上述差异。验证条件变化后回到待校验；旧记录作为历史保存，不能自动升级为新门禁下已确认。

特别处理默认角色：临时选择角色试跑通过，不得直接确认原始 default 脚本可无头回归。保存有版本的角色绑定作为脚本执行配置，或生成明确角色的新版本后重新验证。匿名用例与明确角色步骤不能被默认角色覆盖。

保存一张覆盖矩阵：原始前置条件/步骤/预期 ID → 执行动作 → 断言 → 证据 → 结果。遗漏预期、关键字段未读取、存在未完成人工复核时，不允许确认。

## 6. 模型评测和切换策略

模型切换必须使用同一页面、同一账号、同一数据、同一视口和同一脚本，至少运行 5 次。

记录：

- 首次定位成功率；
- 控件类型识别准确率；
- 分区滚动成功率；
- 断言准确率；
- 脚本回放成功率；
- 平均模型耗时；
- API 错误和重试次数；
- 误判类型。

当前实验结果只能说明：

- `qwen3.8-omni-flash` 在这条详情用例上完成过一次端到端通过；
- `qwen3-vl-plus` 在字段同义词上出现过误判；
- 尚不足以宣布某个模型普遍优于另一个模型。

模型配置界面应显示模型族、视觉输入支持和最近评测结果。模型服务连接失败要单独显示，不应混入定位失败。

## 7. 实施顺序

### 阶段 A：建立基线

交付：运行上下文、诊断日志、固定样本、结果分类。

验收：能区分模型错误、坐标错误、脚本错误、数据阻断和服务错误。

### 阶段 B：修复主链路

交付：干净复跑、分区观察、结构化目标、Element Plus 组件适配。

验收：详情、下拉、开关、表格行四类固定样本各运行 5 次，脚本独立回放全部通过。

### 阶段 C：完善契约和失败控制

交付：前置条件、断言类型、失败分类、有限恢复、角色/环境绑定。

验收：数据不满足时阻断；同一错误不循环；不会通过换对象或削弱断言获得通过。

### 阶段 D：模型评测和性能优化

交付：模型基准、有效 ref 缓存、局部快照、模型耗时和成本指标。

验收：覆盖不降低，正确性稳定后再优化耗时；不以降低断言强度换取速度。

## 8. 验收标准

P0：

- 生成脚本从干净页面独立复跑；
- 角色和登录态可追踪；
- 不可见区域不会被直接判定为不存在；
- 关键控件定位具备作用域、控件类型和动作校验；
- 前置数据缺失时阻断；
- 失败分类准确且无重复循环。

P1：

- 数值、状态、文本和集合断言分离，空值和解析失败不能被转为合法值；
- 下拉选中值不再读取内部搜索 input；
- 视觉判断进入人工复核，不直接转为自动通过；
- 脚本与环境、角色、用例版本绑定。

稳定性目标：固定样本每种配置至少 5 次独立运行；脚本回放通过率达到 100%；模型服务错误单独统计；在不降低覆盖和正确性的前提下，再设定耗时目标。

## 10. 不做的事情

- 不加入渠道、模型、Key 等业务对象的硬编码分支；
- 不用任意 `first()`、`nth()` 或 force click 隐藏歧义；
- 不把 `ai_act` 直接当成可回放脚本；
- 不把截图生成、模型调用成功或人工复核中的视觉判断算成自动通过；
- 不在数据缺失时替换测试对象或权限角色；
- 不在没有重复基准数据时宣布模型切换有效。

## 11. 执行模式与结果落库

### 11.1 执行模式

首期保留“Midscene 探索 + 确定性回放”为默认模式。独立实验中的直接 aiAct/aiQuery 脚本是诊断基线，不证明现有录制器已能转换出等价脚本。

探索动作必须转成有版本的结构化步骤，并能映射到原用例。未录制的 aiAct 恢复、未保存的滚动或变量比较都不能静默遗漏。无法导出时显示“探索完成，尚不能回放”。

后续可新增显式的“视觉运行”模式，用于无法获得稳定 DOM 的页面。此模式报告标明模型、成本和人工复核要求；普通回归失败不得自动切换成视觉运行并覆盖原始失败。

### 11.2 双层结果

保留底层执行状态 passed/failed/error/skipped，新增验收状态 verified_pass/failed/blocked/pending_review/incomplete，以及原因码、覆盖矩阵、证据和恢复记录。兼容现有引擎枚举，不直接把新字符串写入旧字段。

例：截图步骤执行成功，底层可为 passed，但若该步骤承担关键视觉预期，其验收状态必须为 pending_review。只有必需预期全部验证、没有待复核/遗漏，才算 verified_pass 并可确认。

打通 runner → save-run/结果 schema → workflow → 工作台/报告/统计/导出；不能只改 UI 文案。报告分别统计业务断言、数据阻断、会话失败、模型服务错误和定位问题；证据不足标为待归因，不自动标记产品缺陷。

## 12. 交付批次、迁移与回退

| 批次 | 必须交付 | 验收门禁 |
| --- | --- | --- |
| M1：可信结果 | 有效角色和页面绑定、覆盖矩阵、结果分类、复核门禁、确认指纹 | 错角色、缺预期、视觉仅截图三类负例均不能被确认通过 |
| M2：准确执行 | 分区可见性、确定性读取、严格数值比较、组件适配、跨页变量比较 | 真实案例与组件夹具验证数值等价、不同值、空值、重复字段和长抽屉 |
| M3：可靠回放 | 成功路径整理、依赖动作录制、从初始页面独立复跑、有限恢复 | 冷启动与保留登录的重复运行均无残留状态依赖，失败不通过改对象自愈 |
| M4：评测与提效 | 模型对照、统计、局部快照、已验证流程复用 | 相同覆盖下重复比较，通过率与误判率不退化 |

M1 先建立结果和上下文基础；M2 建立可读取、可比较的能力；M3 使用这些能力生成稳定脚本。M4 在正确性达到门禁后进行。待工作量拆分后估算工期，本方案不承诺未经评估的日期。

新动作/断言先升级读取器、代码生成器、调试器和回放器，再开放生成。历史 steps 文件保留；缺少语义或绑定信息的脚本明确要求重验，不能猜测迁移业务目标。按项目开启新流程；出现退化可回退执行策略，但不得回退结果真实性和人工复核门禁。保留旧记录和实验报告，不覆盖用户脚本。

首批建议固定 6 类样本：最后一项不可删除、关键词/类型/状态组合筛选、跨页配置一致性、同名控件和重复表格操作、无登录/登录失效、多角色切换。筛选数据需明确含匹配与不匹配样本、分页边界和数据准备/清理规则。另注入一次服务连接错误，检查恢复和归因。

每个可执行样本目标为 5 次独立回放全部通过，这是小样本交付门禁，不代表生产可靠性为 100%。同时要求所有已知负例不误报通过；记录总样本、数据阻断和环境错误，不通过剔除失败美化通过率。视觉模型只有一次成功时仍显示“单次验证”。

## 实施记录：核心链路补全（2026-11-15）

### 最新探索日志反馈修正

19:13 / 19:14 的实际探索日志证明内嵌角色会话复用、reveal 和字段读取已被调用；19:20 保存被 COVERAGE_INCOMPLETE 拦截，尚不能视为回放通过。检查发现桌面探索提示未同步 assertion_coverage 规则，且 expect_observed 同时收到 name/expected 时会优先取来源变量，存在忽略明确预期的风险。

本轮修正：

- 桌面探索提示和断言工具描述明确覆盖映射要求；缓存合同同时附上原始预期、前置条件编号。
- 明确状态变化不能证明后台行为，禁止为缺少证据的预期补填覆盖编号。
- expect_observed 的变量引用与常量预期互斥，在探索、调试和脚本生成阶段统一检查；未读取的变量禁止生成脚本。
- 提醒 undo 只清除录制，不撤销页面操作，防止整理录制时无依据地重复业务操作。

新增负例覆盖混用 name/expected、缺少来源、错误常量和不存在变量。相关 MCP 测试 18 项通过，桌面测试与构建通过。未自动重跑外部站点上的启停操作；已启动的探索仍持有原始提示，需要新建一次探索才能接收修订规则。
