# 面向 Midscene 的 UI 用例执行格式与验证方案

日期：2026-11-14（Asia/Taipei）
状态：分析与实验方案；生产执行链路尚未接入。实验结果另见 `ui-case-execution-contract-validation.md`。

后续进展：结构化目标与字段断言的生产主路径已实现，最新范围与验证结果见 [代码优化记录](ui-case-execution-contract-implementation.md)。本文保留最初方案及当时能力边界。

## 1. 要解决的问题

现有用例由 `preconditions[] / steps[] / expected[]` 构成，直接拼进探索提示。历史四条样本存在数据未落实、步骤预期错位、配置操作承担运行时断言等问题。Agent 因而同时承担用例补全、页面探索、定位和验收，执行中出现替换模型、重排步骤、收缩断言。

本方案增加一层“执行用例”，保留原始业务用例及覆盖关系。先完成语义审查和环境绑定，再逐个动作编译成 Midscene 定位参数，随后使用现有可录制工具操作。格式清晰只解决信息歧义，不能替代模型能力、坐标校准、组件适配和环境准备。

## 2. 当前能力边界

以本次工作区源码为准，而非此前方案中的设想：

- `browser.ai_locate` 实际接收 `prompt`、可选 `intent=click|fill|check`、可选 `text`。
- `label`、`scope_ref`、`open_select`、`read_selected` 尚不是工具参数。区域和关联标签只能先编译进 `prompt`。
- `text` 用于落点后的文字检查及附近纠偏，不是硬性的身份约束；同名控件仍可能串位。
- `intent` 在 DOM 映射时用于归一化真实控件；Midscene 本身实际收到的是 `prompt` 字符串。
- 已有 Element Plus wrapper 点击、选中值适配、表单项定位等局部能力，但没有通用的区域身份验证。
- 已有录制、代码生成和 Playwright 回放；`ai_act` 不满足现有录制要求。
- 当前 `intent_verified` / `text_verified` 不能证明目标属于要求的业务对象和作用域。

## 3. 推荐格式：业务用例 → 执行用例 → 单目标定位请求

### 3.1 业务层

保留原始用例 ID、原始步骤和每条预期，给预期分配稳定 ID。转换不得删除原始预期，不得把“保存配置”解释为已验证“故障切换次数”。拆分后保留父子关系与覆盖映射。

### 3.2 执行层（JSON 存储，可提供 YAML 编辑视图）

| 字段 | 要求 |
| --- | --- |
| `version / id / title` | 版本化，派生执行用例有独立 ID |
| `source` | 原用例 ID、步骤编号、待覆盖预期 ID |
| `execution` | 精确环境、角色引用、页面入口、数据绑定；凭据不进用例 |
| `targets` | 命名目标：由外到内的区域/对话框/列表行/表单项/选项列表、控件类型、自身文字/placeholder/关联 label |
| `steps` | 一个步骤只有一个动作；输入值或目标布尔状态明确；允许多个结果断言 |
| `assertions` | 明确目标、谓词、期望值与证据方式；配置展示、持久化、运行时行为分别描述 |
| `coverage` | 每条原预期对应哪些动作和断言；未覆盖原因明确记录 |
| `unresolved / status` | 未知信息显式记录；存在阻断项不得标记 ready |

完整生产格式还需增加 `preflight`、`cleanup`、数据准备配方及版本哈希。实验中的最小格式仅支持固定本地夹具和 `value / text / checked` 结果，不宣称已实现通用转换器或生产执行器。

### 3.3 单个目标的写法

```json
{
  "page": "模型管理",
  "scope": [
    { "kind": "dialog", "name": "编辑模型", "key": "MODEL-UI-001" },
    { "kind": "region", "name": "故障切换配置" },
    { "kind": "form_item", "name": "备用渠道" }
  ],
  "control": "combobox",
  "label": "备用渠道",
  "name": "备用渠道"
}
```

编译成当前工具支持的请求：

```json
{
  "prompt": "在「模型管理」页面的对话框「编辑模型」（对象 MODEL-UI-001）内，进入区域「故障切换配置」的表单项「备用渠道」，定位标签「备用渠道」对应的下拉框，用于打开选项。目标必须能由这些条件唯一确定。",
  "intent": "click"
}
```

这里不把旁边的标签机械塞进 `text`；只有明确知道目标自身文字或 placeholder 时才传入。所有例子里的对象名和入口必须由实际项目绑定，不能直接当作真实环境已有数据。

面向用例编写者，可显示为下面的表单；底层存储上述结构，不要求人工写定位器：

| 项目 | 示例 |
| --- | --- |
| 页面 | 模型管理 |
| 目标区域 | 编辑模型（MODEL-UI-001）→ 故障切换配置 → 备用渠道 |
| 控件类型 | 下拉框 |
| 关联标签 | 备用渠道 |
| 本步动作 | 打开选项 |
| 本步预期 | 与该字段关联的选项列表可见 |
| 后续动作 | 在该选项列表选择精确名称“阿里云源” |
| 后续预期 | 该字段展示选中值“阿里云源” |
| 缺失时处理 | 停止，报告目标缺失或候选歧义 |

推荐描述模板是“页面 → 区域 → 对象 → 控件 → 一个动作 → 具体结果”，不把像素坐标、DOM ref、CSS、模型选择策略写进业务用例。

### 3.4 原子动作与状态

| 业务动作 | 当前可执行展开 | 验证 |
| --- | --- | --- |
| 输入关键词 | `ai_locate(intent=fill)` → `type` | 输入值正确；查询动作另列；结果集合按固定数据校验 |
| 开启开关 | `ai_locate(intent=check)` → `check(true)` | 状态为 true；再次执行保持 true |
| 选择备用渠道 | 定位并点击下拉框 → 等待关联选项列表 → 定位并点击精确选项 | 组件选中展示值；关联选项列表需唯一 |
| 编辑某模型 | 先按稳定业务键限定行，再定位该行编辑按钮 | 抽屉对象身份与该行一致 |
| 保存 | 限定当前表单/对话框按钮，点击一次 | 成功提示；需要验证持久化时重新打开读取 |

禁止把“进入页面、编辑某模型、选择备用项、保存并验证不循环”写成一个 Midscene 请求。执行状态采用条件等待，不以固定 sleep 判断完成。数据不存在、目标歧义、页面不匹配或期望无法观察时停止。

## 4. 转换与准入流程

1. 提取原始用例，不改原文；去掉重复编号后分配步骤与预期 ID。
2. 语义审查：逐条检查动作是否触发预期、预期是否可观察、是否混合互斥状态；语义判断不能仅靠正则和数组等长。
3. 拆分场景：有效/无效数据，有候选/无候选，页面配置/服务端执行分别成例；保留所有原预期的去向。
4. 绑定项目资料：精确角色、唯一业务对象、页面入口、数据准备及清理方式。未知项进入 `unresolved`，禁止补造事实。
5. 形成执行用例草稿；若只是确定性格式转换可自动处理。业务含义不确定时标记待澄清，不让执行 Agent 自行决定。
6. 静态校验：字段、引用、动作值、断言、覆盖对应关系；预检：角色、环境、数据、页面版本和观察能力。
7. 仅 ready 用例进入探索；每步只发送当前目标和当前动作上下文。
8. 保存确定性脚本，恢复前置状态后独立回放；记录每条预期的证据与未完成项。

生产状态建议区分 `draft / needs_clarification / ready / blocked_environment / executing / passed / failed / partial`。实验状态简化为 `draft / blocked / ready`，避免把实验原型误当作完整工作流。

## 5. 四条历史用例的转换结论

| 原用例 | 转换方向 | 必须保留的待补信息 |
| --- | --- | --- |
| 筛选分页 | 筛选与分页分别规定输入、数据集和预期集合；可串成流程 | 环境角色、唯一模型数据、关键词、页大小、筛选后是否跨页 |
| 启用停用 | UI 状态切换与新请求路由验证分别成例 | 模型身份、初始状态、健康与授权条件、路由观察方式 |
| 自定义路径 | 非法路径参数化、合法保存、匹配语义分别成例 | 修正步骤预期对应关系、每类非法输入、大小写初始值、匹配证据 |
| 故障兜底 | 配置保存、有/无候选、运行时切换次数分别成例 | 主备对象、故障注入、请求输入、调用链/次数证据、恢复方式 |

四条历史用例在这些信息落实前都不能直接产出 ready。测试夹具自行定义的数据只用于验证格式与工具衔接，不回写成真实业务事实。

## 6. 生产接入建议

第一阶段：增加执行格式与转换审查产物；修复 `data_refs` 识别与覆盖问题；移除“相近角色自动等价”的默认假设；以覆盖完整性和环境绑定作为探索准入条件。

第二阶段：编排器按步骤编译 `prompt / intent / text`；保存 sourceExpectedId 到录制及报告。为 `ai_locate` 增加真正的作用域/对象身份验证，校验解析后的定位器是否仍指向原目标。仅把区域写进 prompt 不能承担这一保证。

断言的定位器必须以对象身份和字段身份构造，预期值单独参与比较。禁止用 `hasText: 预期值` 在全页挑一个字段，再断言它等于该预期值。本次反例已复现：兜底字段实际是“错误渠道”、普通路由字段是“阿里云源”时，现有生成断言仍可通过；实验中限定“故障切换配置”区域后能正确拒绝。这是生产接入前必须补齐的约束，详细数据见验证报告。

第三阶段：补充组件状态断言（尤其 checked）、关联弹层与选择适配；持久化、请求/调用链、数据库证据接入；增加数据恢复与跨版本失效控制。

第四阶段：验证同一业务覆盖下的探索成功率、操作成功率、耗时和独立回放率，再批量转换历史用例。

## 7. 本次实验设计（测试前确定）

### 7.1 结构验证

使用可执行 Schema 和语义校验原型，覆盖未知目标、动作/控件类型不符、漏断言、漏覆盖、未知角色/数据、未解决问题冒充 ready 等负例；四条历史用例输出阻断清单。

### 7.2 真实 Midscene 定位对照

构造可重置本地 HTML 夹具，包含相邻同名搜索框、开关、下拉框、选项、列表编辑按钮和保存按钮。使用现有 `midsceneFactory`、`BrowserSession.locateAt`、操作和录制代码。

- A 组：简略目标描述。
- B 组：由执行格式编译的“页面 + 区域/行对象 + 控件类型 + 文字/标签 + 动作目的”描述。
- 两组共享 `intent` 和 `text`，隔离描述变化；不更换模型或模型族来人为改善 B 组。
- 每类目标 3 轮，交替 A/B 顺序；轮次调整区域/行顺序，记录视口、DPR、模型族、版本。
- 每次操作恢复初始页面，关闭定位缓存；不做人工纠偏和工具层重试。
- 真实模型不可用时记录阻塞，不用模拟坐标替代真实视觉成绩。

夹具中的 data-testid 和 DOM 框仅供独立评分、操作后断言与现有录制生成器使用，不进入定位 prompt，不用于给模型提供正确坐标。简略描述的歧义样本用于研究指代能力，不代表所有旧用例的平均质量。

### 7.3 指标与判定

分别记录原始落点命中、映射后目标身份、实际操作成功、正确业务结果、模型耗时及错误类型。错误目标上的一次“点击成功”不能算正确操作。纠偏后的命中不得计作原始视觉命中。

对 B 组正确操作生成 spec，使用新浏览器上下文恢复夹具后独立运行生成的 Playwright 脚本，回放不调用模型。checked 等当前录制器不支持的直接断言应明确列为实验观察断言，并通过页面状态文字录制可回放断言，不伪造已支持的工具。

在完成模型族对照后，追加一个六步连续流程：输入目标模型 → 编辑指定行 → 开启故障切换 → 打开备用渠道 → 选择选项 → 保存。该流程不在步骤间重置页面，验证先打开弹层再选择的状态依赖；探索完成后生成一份 spec 并独立回放三次。夹具无真实后端，因此不验证实际持久化或故障路由。

本次仅评估格式可行性。小样本不做 P95、显著性或普遍提速承诺；不从本地 HTML 夹具推断真实 Element Plus、Electron 缩放和业务故障链路已通过。真实环境验收仍需落实第 5 节条件。

### 7.4 首轮观察触发的补充实验

当前配置的前六类样本显示结构化描述仍存在系统性坐标偏差。例如平台模型输入框的实际范围为 x=674～934、y=142～180，结构化请求返回中心 `[625,175]`。当前模型名为 `qwen3.8-omni-flash`，自动模型族为 `qwen2.5-vl`。

核对已安装 SDK 的 `ai-model/models/qwen.js`：`qwen2.5-vl` 使用未归一化坐标，`qwen3-vl` 使用 `normalizedBy: 1000`。该差异与观察到的偏差相符，但不能只凭单点推断模型兼容性。

因此保留当前配置完整 A/B 结果，再以同一模型、同一夹具、同一描述和轮数，单独运行 `qwen3-vl` 适配实验。仅改变实验进程的模型族，不修改用户设置。分别比较各模型族内 A/B，不将跨模型族提升全部归因于用例格式。

模型族同时影响图像预处理、坐标解释和请求参数，所以该补充实验验证的是适配配置整体，不是只对一个坐标公式做单变量实验。不能从结果推断该模型名称已获得 SDK 官方兼容认证。
