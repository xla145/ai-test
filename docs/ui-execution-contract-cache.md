# UI 用例转换与脚本复用

日期：2026-11-14

## 执行方式

点击生成脚本后，先在代码中检查缓存，而不是直接启动探索 Agent：

1. 用例没有步骤或预期：直接提示补充，不调用模型。
2. 没有有效转换结果：单独启动转换任务，要求返回结构化 JSON。代码校验原始前置条件、步骤、预期没有遗漏或改写，角色精确匹配，交互动作具备已知 target 或待页面确认的 targetHint，开关具备明确状态。
3. 转换为 `needs_clarification`：保存原因并停止，不进入 UI 探索；下次条件未变化时直接显示已保存原因。
4. 转换为 `ready`：把已保存计划交给探索 Agent，定位并录制 Playwright 脚本。
5. 下次生成时，计划、用例、环境和脚本版本完全一致：直接返回已有脚本，AI 调用为 0。界面仍按原流程试跑和确认。
6. 只有计划有效而没有可复用脚本：跳过转换，进入探索。

转换与探索是两个独立任务；首次使用增加一次转换调用，其目的是让后续重试和重复生成不再重复整理。两阶段共享本次生成的 token 上限，已消耗用量分别入账。转换任务使用只读沙箱，提示中禁止工具调用和页面操作；这不是对远程 MCP 工具的独立权限隔离。

## 保存与失效

缓存存放在项目工作区 `.aitest/ui-contracts/<项目、环境、用例组合的哈希>.json`，不是全局共享文件。写入使用唯一临时文件和原子重命名。

文件保存格式版本、输入指纹、计划及计划内容哈希，以及生成脚本和结构化录制文件的哈希。输入指纹涵盖标题、步骤、预期、前置条件、data_refs、角色名和环境配置。环境配置只进入哈希，不原文保存；不读取或写入钥匙串凭据。计划本身保存用例已有的描述和输入值。

以下变化使相应缓存失效：

- 用例内容、角色列表、环境配置或转换规则版本改变：重新转换。
- 脚本或录制文件改变/缺失：不直接复用旧脚本，保留有效计划。
- 缓存损坏或计划被修改：不信任旧缓存。
- 转换期间用例变化：不进入探索；探索期间变化：不把新脚本绑定为可复用版本。

录制文件新增 `caseHash` 和 `generationId`，避免把旧文件误报为本次新生成的脚本。旧脚本没有这些来源信息，不自动建立可信缓存；原有回归和调试仍可使用它们。首次重新生成后建立关联。

## 边界

- 缓存只表明生成来源一致，不代表当前页面或数据正确。返回复用脚本不会执行浏览器，也不会自动标记校验通过。
- 首次探索仍可能调用 Midscene；本次未增加跨页面的视觉坐标/selector 缓存。
- 正式回归继续运行 Playwright。页面变化造成脚本失败时，通过已有单步调试或“修正脚本”入口处理，不在每次回归时重新转换用例。
- 结构校验能够发现覆盖遗漏、非法角色和部分动作类型错误，不能证明 AI 的业务语义判断完全正确。未知条件仍须人工补充。

## 验证

使用可计数的 Agent 替身测试编排逻辑，未把模拟 token 数量当成真实模型节省比例：

| 场景 | 实际模型入口调用次数 |
| --- | --- |
| 首次生成 | 2 次：转换、探索各 1 次 |
| 重启编排器后重复生成 | 新增 0 次，返回 tokens=0 |
| 首次未生成脚本，再次尝试 | 累计 3 次：转换 1 次、探索 2 次 |
| 待澄清用例重复尝试 | 累计 1 次转换，无探索 |
| 前置条件、预期、数据依赖、环境或角色变化 | 重新转换和探索 |
| 脚本或录制内容被修改 | 复用计划，仅重新探索 |
| 非法转换 JSON、丢失原始预期 | 阻止进入探索 |

入口：`desktop/test/ui-contract-cache.test.ts`、`mcp-servers/test/ui-contract.test.ts`。

最终验证：桌面 21 个测试文件、136/136 通过；MCP 13 个测试文件、73/73 通过（单 worker，使用已有 Python 依赖包装入口）；MCP 与桌面主进程/渲染端类型检查通过，`git diff --check` 通过。本轮没有调用真实模型测量 token 节省量。


## 2026-11-14：修复转换前置检查过严

转换缓存规则升级至版本 2。旧版本因缺少页面标题、控件类型、抽屉结构或菜单区域而产生的待澄清缓存自动失效，不需要删除登录态或手动清理整个缓存目录。

交互动作可以保存 `targetHint`，如“后台左侧导航中的渠道管理菜单项”；首次探索根据实际页面解析控件与区域并校验唯一性。业务对象缺失、角色未配置等仍需澄清，不自动选择任意渠道执行修改。原用例明确允许“按钮禁用或点击后提示”时，保留两种可接受实现，而不是强迫用户预先指定一种。

待澄清响应中的残缺 target 不再导致整个结果无法保存：移除无法执行的定位字段，保留原始用例和阻塞原因。可执行计划中的非法结构化 target 仍严格拒绝。

验证：相关桌面测试 20/20、契约测试 6/6 通过；完整类型检查通过。本次是日志复现与自动化验证，尚未在真实业务页面重新执行用例。
