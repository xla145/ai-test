# Midscene 视觉辅助

客户端已内置 `@midscene/web` 1.17.7，共用 UI 工作台的内嵌浏览器，无需单独安装浏览器插件。

## 启用

1. 在全局设置 → 模型中添加支持图片输入的模型，填写服务地址、模型名和 API key。
2. 按实际模型选择「Midscene 视觉模型族」。常见模型名可自动推断；方舟 `ep-…`、私有部署别名需要手动选择，例如 `doubao-seed` 或 `qwen3-vl`。
3. 在用途分配中将该模型选为「视觉模型」。保存后新建的探索会话使用新配置；已有任务结束后重新开始。
4. UI 测试工作台会显示所选模型。配置状态仅表示已选择模型，实际推理仍需服务支持视觉输入。

API key 保存在系统钥匙串，通过环境变量传给浏览器 MCP 服务，不写入 Codex 的 TOML 配置。设置中的连通性检查只检查服务，不保证视觉推理可用。

## 测试流程

选择用例 → AI 探索内嵌浏览器并生成脚本 → 用户在浏览器中校验、修正 → 审核脚本 → 执行回归。

- `ai_locate`：常规页面快照找不到元素时，用视觉定位并转换成可录制的 DOM 引用；高分屏与内嵌浏览器缩放（按 1280 桌面宽度渲染后缩小显示）下坐标都按页面实际画面换算。
- `ai_assert`：视觉判断进入人工复核队列，不能直接当作用例通过。响应包含 Midscene 报告路径。
- `ai_act`：探索工具，不录入脚本；需要使用常规点击、输入重新录制。常规探索仍优先用可录制操作。
- 普通回归执行已生成的 Playwright 脚本，不调用 Midscene，不消耗视觉模型。

报告和缓存默认位于客户端数据目录的 `midscene/` 下（数据目录见全局设置 → 运行环境）。报告可包含页面截图与模型交互；按被测项目的数据管理要求保存和清理。

关闭视觉模型用途后，新探索会话不再暴露视觉工具，普通浏览器操作和脚本回归继续可用。

## Qwen3-VL 与结构化定位

使用 Qwen3-VL 时，模型名填写服务商实际提供的名称（例如 `qwen3-vl-plus` 或 `qwen3-vl-flash`），视觉模型族选择 `qwen3-vl`，并在用途分配中选为视觉模型。标准 Qwen3-VL 名称支持自动识别；自定义部署别名建议显式指定。保存后新建探索任务使用新配置。

`ai_locate` 支持结构化 `target`，服务端自动生成单目标描述：

```json
{
  "target": {
    "page": "模型管理",
    "scope": [
      { "kind": "region", "name": "平台模型" },
      { "kind": "row", "name": "模型记录", "key": "实际模型编号" }
    ],
    "control": "button",
    "text": "编辑"
  },
  "intent": "click"
}
```

`page` 为定位描述提供页面上下文；`scope` 按页面实际 DOM/可访问语义验证，支持 region、dialog、row、form_item、listbox。范围、业务 key、控件类型和名称/标签必须唯一匹配；缺失或歧义时返回错误。关联标签放 `label`，输入框占位文字放 `placeholder`，不要把旁边文字写成目标自身 `text`。打开下拉框与选择选项分两步执行。

结构化目标的范围会保留到录制与回放；旧 `prompt` 调用仍兼容，但不具备显式范围验证。新的字段取值断言不允许依靠预期值选择另一个字段。用例角色必须精确匹配配置，数据引用为空时也要核对文字前置条件。

已有脚本不会自动重写。此前存在定位歧义或断言串位的用例需要重新探索、生成脚本，再独立回放校验。
