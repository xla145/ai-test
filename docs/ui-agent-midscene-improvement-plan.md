# UI 测试 Agent 定位与执行效率改进方案

日期：2026-11-13（Asia/Taipei）
状态：待实施；本文记录方案，不代表改造已完成。

## 1. 背景与目标

UI 用例探索存在耗时长、控件定位反复失败、录制结果无法稳定回放的问题。项目已接入 Midscene，并已增加“UI 探索定位策略”设置，当前用户配置为优先 Midscene。

切换策略后，新任务确实开始优先调用 `browser.ai_locate`，但定位到可录制操作的转换仍不稳定。方案重点是提高一次定位和操作成功率，减少无效模型往返，同时保证用例条件、断言和回归脚本的正确性。

目标：

- 探索时优先使用 Midscene 获取新的操作目标；已有有效 ref 可复用。
- 工具负责控件识别、操作适配、唯一定位器生成和可恢复错误处理。
- 生成确定性 Playwright 脚本，日常回归不依赖视觉模型。
- 前置条件不满足时明确阻塞，不擅自换数据、换权限或减少断言来获得通过。
- 用日志和固定样本验证效果，不预设“视觉优先一定更快”。

## 3. 问题定位

### 3.1 模型族与坐标链需要验证

当前视觉模型为 `qwen3.8-omni-flash`，未显式配置模型族，运行时使用 `qwen2.5-vl`。`visionFamilyOf` 对未识别的 Qwen 名称执行了这一兜底。

这属于兼容性疑点，尚不能直接认定为偏移根因。还需检查 Electron 缩放、CDP 截图尺寸、Midscene 内部图像归一化和返回坐标的关系。当前代码认为返回 center 已是 CSS 坐标，不能未经验证再次除以 DPR。

### 3.2 视觉结果映射缺少动作语义

当前链路：`aiLocate → center/rect → locateAt → elementFromPoint/附近文字 → ref`。

`locateAt` 主要依据落点、祖先面积和文字匹配选元素。附近文字搜索默认半径为 150 CSS 像素；匹配文字后可能直接返回叶子文本，而非对应控件。无目标文字时也可能返回非交互容器。

`verified=true` 目前只说明文字检查通过，不说明能够点击、输入、切换或读取选中值。

### 3.3 组件语义与原生元素语义混用

当前 `click`、`select`、`check`、`expectValue` 直接使用 Playwright 原生元素操作。Element Plus 下拉框不是原生 select，内部 input 的值与选中展示值不同。继续依靠 agent 换工具、换 ref，会反复遇到相同问题。

### 3.4 定位器生成与目标身份脱节

当前 `pickUnique` 主要检查候选匹配数量为 1。全局文本、通用 CSS 可能受到隐藏副本和重复内容影响；当前已支持部分列表行范围，但缺少充分的抽屉、表单项等范围信息。

仅检查唯一还不够：唯一候选必须与实际视觉目标一致，并满足相应操作条件。

### 3.5 恢复流程缺少边界

最新日志出现“点击失败 → 截图 → 再点同类 input → 文本断言失败 → 读取 input 值失败 → 再视觉定位”。这些步骤没有形成有效进展。

现有任务级 token 限制不能替代目标级重试控制。相同页面导航、缺失数据搜索和过大的操作后快照也持续增加模型往返成本。

## 4. 改造设计

### 4.1 P0：增加诊断证据并校准模型与坐标

需求编号：UI-01。

每次视觉定位保存关联记录：模型名、模型族、页面 URL、截图宽高、`innerWidth/innerHeight`、DPR、Electron zoom、视口及滚动信息、原始 center/rect、最终元素框、调整距离、调用耗时。

生成叠加目标框和落点的诊断图，用于判断偏差发生在模型输出、坐标换算还是 DOM 映射阶段。默认保存在本地证据目录，沿用证据清理策略，不记录凭据。

核对当前模型在所用 Midscene 版本中的定位支持方式。不能确认兼容的模型应显示“定位兼容性未验证”，提供定位校准入口；不要仅凭名称猜测模型族。

验收：

- 固定页面上的菜单、输入框、下拉框、开关、列表按钮各有可复现校准样本。
- 确定性坐标夹具在不同缩放下映射到同一目标元素。
- 实际模型定位单独统计命中率，与坐标转换测试分开。
- 错误模型族或未验证配置能被识别，不能静默当作已验证配置。

### 4.2 P0：让视觉定位感知目标动作

需求编号：UI-02。

扩展 `ai_locate` 输入，保留现有字段兼容，新增可选字段：

```json
{
  "prompt": "故障切换区域的备用渠道下拉框",
  "intent": "open_select",
  "label": "备用渠道",
  "scope_ref": "已识别的抽屉或表单区域 ref"
}
```

`intent` 首期支持点击、输入、打开下拉框、设置开关和读取选中值。`label` 表示控件关联标签，不能等同于控件自身必须包含的 `text`。

映射时结合关联 label、ARIA、局部容器和组件特征查找实际控件。附近文字纠偏必须限制在正确作用域内；重复文字或歧义无法消除时返回结构化错误，不默认取最近文字。

返回值分别描述文字匹配、动作类型匹配、目标唯一性和可操作性。输入框请求不能以整个容器作为成功结果，开关请求不能以静态标签作为成功结果。

验收：搜索框可输入；开关可读取并设置状态；相邻同名控件不串位；无可操作目标时明确失败。

### 4.3 P0：补齐 Element Plus 组件适配

需求编号：UI-03。

适配层集中处理控件，不将框架细节交给 agent 反复推理。

| 控件/动作 | 适配要求 |
| --- | --- |
| 下拉框打开 | 找到所属 wrapper，在正确滚动容器中使其可见，检查遮挡 |
| 下拉选项选择 | 关联对应 listbox，限定选项范围，等待弹层稳定 |
| 下拉选中值断言 | 读取展示标签或组件可访问状态，不读取搜索 input 代替 |
| 输入框填写 | 定位实际可编辑 input/textarea，校验可编辑性 |
| 开关设置 | 使用 checkbox/switch 语义，设置目标状态而非盲目点击 |

优先利用标准 ARIA 和 label 关系，Element Plus 特征作为适配分支。不得通过普遍启用 force click 掩盖遮挡；无法消除遮挡时返回阻塞原因。

适配后的动作必须能序列化到录制步骤，并由代码生成器和回放执行器使用一致语义。新增动作类型时同步更新旧步骤兼容、调试、导出与回归路径。

验收：包含 readonly 内部 input、teleport 弹层、隐藏选项副本、抽屉 footer 遮挡、重复标签、开关初始状态不同的测试场景；探索成功后独立回放仍成功。

### 4.4 P0：生成有作用域且指向原目标的定位器

需求编号：UI-04。

扩展现有行范围定位机制，覆盖抽屉/对话框、表单项、列表行等稳定上下文。每层范围应具有可复现语义，避免把动态 DOM 路径直接写入脚本。

返回可操作 ref 前验证候选定位器：

1. 在目标作用域内唯一。
2. 解析结果与采集到的目标为同一元素或经适配确认的对应控件。
3. 满足当前动作要求；操作时再次检查页面变化。

可见性可用于排除隐藏副本，但不能用任意 first/nth 掩盖多个可见候选。无法唯一定位时返回候选范围及冲突原因。

验收：两个同名字段、多个编辑按钮、隐藏弹层副本下，录制与独立回放均操作正确目标；不能仅验证页面某处出现了预期文字。

### 4.5 P1：统一失败分类与有限恢复

需求编号：UI-05。

建议错误分类：模型调用失败、坐标无效、目标缺失、目标类型不匹配、定位歧义、元素被遮挡、ref 失效、前置数据缺失、断言不成立。

以用例步骤、目标语义、动作和页面状态作为失败标识，避免更换 ref 后被当成全新问题。首期建议同一目标最多执行一次有依据的恢复；仍失败则停止该步骤并记录证据。该次数为待验证的默认策略，不是现有实现。

恢复必须产生变化，例如重新滚动、等待弹层稳定、限定作用域或切换组件适配。禁止重复发送同一失败点击、仅改写提示词重复定位，或通过削弱断言使测试通过。

前置数据不存在或角色不满足要求时，返回阻塞。替代数据、角色需要事先声明等价规则；不能由 agent 自行推断最接近角色即满足权限要求。

验收：同一失败不会无限重复；恢复操作及原因可追踪；前置条件不满足不标记为测试通过；故障兜底用例必须实际覆盖其故障场景。

### 4.6 P1：减少不必要的模型往返

需求编号：UI-06。

- 保持 Midscene 优先，但已有可靠 ref 不重新视觉定位；页面导航、目标重建等情况下使其失效。
- 取值和断言使用确定性组件工具；不为每个断言再次调用视觉模型。
- 操作后快照优先返回当前弹层、表单或变化区域，并对元素数量与文本同时设预算；提供展开完整快照的方式。
- 页面入口和公共前置流程可在验证后复用，按项目、环境、角色和页面版本隔离，失败即回退重新探索。
- 初期不恢复未经验证的视觉坐标缓存。缓存优先保存已验证的语义定位器，并检查有效性。
- 可考虑单个工具封装“视觉定位 → 目标校验 → 确定性操作 → 录制”，但需保留各阶段审计记录，不能直接用不录制的 `ai_act` 替代。

## 7. 验证方法与验收标准

### 7.1 固定比较条件

选择筛选分页、下拉编辑、启停状态、故障兜底四类用例。每次运行前恢复同一环境、账号权限、租户、数据和页面初始状态；记录模型、模型族、视口、缩放、客户端版本。

每条用例每种配置建议至少运行 5 次，同时记录冷启动和后续运行。不同用例、不同初始数据的日志不能直接用于声称提速；小样本不据此推断稳定的 P95。

### 7.2 指标

| 指标 | 定义 |
| --- | --- |
| 探索总耗时 | 任务启动至成功保存且试跑完成，或明确阻塞/失败 |
| 模型与工具阶段耗时 | 单独记录视觉请求、其他工具、调用间隔，不把间隔全算作推理 |
| 首次操作成功率 | 首次定位后，无额外纠偏重试即可完成目标操作的比例 |
| 视觉原始命中率 | 原始落点正确命中目标，不包含附近文字纠正后的成功 |
| 目标映射成功率 | 正确获得可操作、可唯一定位目标的比例 |
| 重复失败次数 | 相同目标、动作和错误原因的重复调用次数 |
| 脚本回放成功率 | 恢复初始状态后独立运行生成脚本的成功率 |
| 覆盖完成度 | 原始步骤、前置条件和预期结果实际验证情况 |

### 7.3 建议验收门槛

以下为目标，尚未达到：

- 固定组件夹具全部通过，错误状态不会被伪装成成功。
- 每条可执行样本用例的 5 次独立回放全部通过；阻塞用例单独统计，不计入通过。
- 同一目标最多一次有依据的恢复，超过后明确停止；不能以更多截图和相同点击继续循环。
- 不出现“静态标签当开关”“搜索 input 值当选中值”“非唯一定位器延迟到断言才发现”的已知错误。
- 在覆盖相同、完成率不降低的条件下，探索耗时中位数较固定基线降低至少 30%；未达标则复核往返次数和视觉调用成本，不放宽正确性要求。

## 8. 发布、兼容与回退

保留 DOM 优先与 Midscene 优先两种设置，新设置对下一次探索任务生效。执行中的任务保持启动时策略，避免中途改变定位规则。

工具新增字段保持可选；新录制步骤需要明确版本和旧步骤读取兼容。回退到 DOM 优先只能切换定位入口，不能撤掉修复后的组件适配、唯一定位和前置条件检查。

先用固定样本验证，再扩大用例范围。出现覆盖下降、错误操作或回放退化时暂停扩大范围，保留对应日志与诊断图。
